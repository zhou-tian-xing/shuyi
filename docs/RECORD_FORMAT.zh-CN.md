# 棋谱文件（`.syp`）的数据结构

`.syp` 是 UTF-8 文本，一行一条记录，行首关键字决定这一行是什么。它同时是**棋谱**（着法树）和
**分析存档**（每个局面的数字），后者是可选的：只有着法的文件照样能打开、能下。

本文是格式的权威定义；代码在 `ui/src/game_record.cpp`（`GameRecord::save` / `load` /
`loadAnalysisLine`），解析的单元测试在 `ui/tests/test_game_record.cpp`。

## 整体形状

```
# shuyi record v2
ruleset classic
moves e5:1 f4:3 d4:1 (c3:2 ) e6:3
#node e5:1/f4:3 wr 0.5800 visits 5000 proven 0 nodes 9000 ms 900 best d4:1 score 2.5000 backend cuda
#cell e5:1/f4:3 d4:1 0.5800 5000 0 1 2.5000
#cand e5:1/f4:3 d4:1 0.5800 5000 2.5000
```

四类行：

| 行 | 必需 | 内容 |
|---|---|---|
| `# ...`（其它 `#` 行） | 否 | 注释。版本头 `# shuyi record v2` 也是注释，读的时候不看版本号 |
| `ruleset <名字>` | 否 | 规则集：`classic` / `blocking` / `nopass`。缺省用当前界面的规则集 |
| `moves <着法序列>` | 是 | 着法树。变着写在括号里 |
| `#node` / `#cell` / `#cand` | 否 | 某个局面的分析：位置本身、它算过的格子、它的候选着法 |

行序无关：`ruleset` 可以写在 `moves` 后面，分析行也可以混在中间（`save` 写的时候是
头部 → `moves` → 分析）。

## 着法：`moves`

着法写作 `a4:2`（坐标:数字，和引擎协议里 `play` 的写法一致；`a4-2` 也接受），过手写作 `pass`，
用空格分隔。

变着用括号，**跟在它所替换的那一手后面**（PGN 的语义）：

```
moves a4:2 b2:5 (c3:1 ) d4:7
```

读法：`a4:2`，然后 `b2:5`；`(` 开始一个"替换 `b2:5`"的变着，所以 `c3:1` 的父节点是 `a4:2`；
`)` 之后回到 `b2:5`，`d4:7` 接在 `b2:5` 后面。

树的结构：

* 一个节点 = 一个局面，由父局面走一步 `move` 到达；
* `children[0]` 是**主干**（最先走的那一手，界面上不缩进的那一行，走势图跟着它走）；
* 走一步已经存在的着法会复用那个节点，所以它的分析不会因为来回翻而消失；
* 着法序列末尾（最深的那条主线）就是打开文件后停留的局面。

## 分析行里的路径

分析行的第一个字段是 `<path>`：从空棋盘走到这个局面的着法序列，用 `/` 连接，写法与 `moves` 相同。

| 路径 | 是哪个局面 |
|---|---|
| `.` | 空棋盘 |
| `e5:1` | 走了 `e5:1` 之后 |
| `e5:1/f4:3/c3:2` | 走了这三手之后（注意 `c3:2` 在这里是第二手的变着，父节点是 `e5:1/f4:3`） |

用路径而不是节点编号：编号是树的实现细节，删一枝就全部重排；路径是外部含义，和文件里其它部分
对得上。指向文件里不存在的着法时，整次载入失败并报 `analysis for a move that is not in the record`。

## `#node`：一个局面的分析

```
#node <path> wr <f> visits <i> proven <0|1> nodes <i> ms <i> best <move|-> score <f|-> [backend <name>]
```

键值对，顺序随意，未知的键跳过（给以后的版本留余地）；键和值各占一个空格分隔的字段。

| 键 | 类型 | 含义 |
|---|---|---|
| `wr` | 0~1 的小数 | 胜率，**行棋方视角**。4 位小数 |
| `visits` | 整数 | 这次搜索在这个局面的根访问数 |
| `proven` | `0` / `1` | 这个局面已被精确解出（残局求解），`wr` / `score` 是精确值而不是采样 |
| `nodes` | 整数 | 这次搜索展开的节点数（协议里的 `nodes`） |
| `ms` | 整数 | 这次搜索花掉的墙钟毫秒（协议里的 `elapsed_ms`） |
| `best` | 着法或 `-` | 引擎选的那一手；空局面或无法给出时是 `-` |
| `score` | 小数或 `-` | 预期终局分（含 A值），行棋方视角；`-` 表示引擎没有分数来源 |
| `backend` | 字符串 | `cpu` / `cuda`。缺省为空 |

有 `ms` 和 `visits`，界面上"分析量 · 速度"（`4.2k 次 · 1.6k/秒`）就是这两个数算出来的，重新打开
棋谱也能看到当时的速率。

## `#cell`：某个格子的分析

```
#cell <path> <move> <wr> <visits> <proven> <has_score> <score|->
```

一行一个格子，位置字段固定（空格分隔，顺序不可换）：

| 字段 | 含义 |
|---|---|
| `<move>` | 这一格的着法（`a4:2`）。过手不是格子，不会出现在这一行 |
| `<wr>` | 胜率，行棋方视角，4 位小数 |
| `<visits>` | 这个子树的访问数 |
| `<proven>` | `0` / `1`：这个子树的胜负已解出，`wr` / `score` 精确 |
| `<has_score>` | `0` / `1`：`score` 是真的（精确目差，或带分数头的采样均值） |
| `<score>` | 预期终局分（含 A值），行棋方视角；`has_score=0` 时写 `-` |

棋盘上的标记和左下角"选点"列表用的就是这些格子：`has_score=0` 的格子显示 `--`，不是 0。已解算
但 0 访问的格子（残局求解不模拟）也是数据，靠 `proven` 而不是访问数判断。

## `#cand`：候选着法列表

```
#cand <path> <move> <wr> <visits> <score>
```

对应协议 `info` 里的 `moves`（引擎排过序的候选），位置字段固定。界面用它来判断"这一手引擎当时
是怎么评价的"，也就是棋谱行左边那小块颜色的减数。

## 数值与规范形式

* 小数一律 4 位（`%.4f`），`-0.0000` 归一成 `0.0000`；
* `save` 是规范化的：`save(load(save(x))) == save(x)`，由测试钉住；
* 载入后每个节点的分析带一个"第几次搜索"的运行时编号（不写进文件，载入时为未知）；界面的覆盖
  规则用它区分"同一次搜索里更旧的快照"和"另一次搜索的数字"，详见 `ui/README.md`。

## 兼容性

* 所有分析行都以 `#` 开头，也就是注释：只认识 `moves` 的旧程序（1.1）打开带分析的棋谱，看到的是
  同一局棋，只是没有数字，保存时那些行会丢——这正是"分析是可选字段"的意思。
* 版本头统一是 `# shuyi record v2`；读的时候不看版本号，看的是有哪些关键字。加新关键字不需要升
  版本（旧程序会当注释跳过），改已有字段的含义才需要。
* 文件里带着规则集：同一串着法在不同规则下不是同一局棋，载入时按文件里的规则集重建局面。

## 错误处理

载入失败会带着原因返回，界面弹窗显示，不会带着半个棋谱继续跑：

| 情况 | 报错 |
|---|---|
| 括号不配对 | `unbalanced '(' in the record` / `unbalanced ')' in the record` |
| 着法写错 | `not a move: zz:1` |
| 规则集不认识 | `unknown rule set: xxx` |
| 分析行指向不存在的着法 | `analysis for a move that is not in the record: e5:1/...` |
| 分析行字段不对 | `bad win rate: ...`、`truncated cell line: ...` 等 |
| 没有任何着法 | `the record has no moves` |
