# 1 小时服务器训练实跑报告

本次是**真实服务器运行**，不是本地模拟。机器：Ubuntu 22.04、RTX 3080 10 GB、
8 vCPU、15 GB 内存、CUDA 12.4 驱动；PyTorch 2.4.1+cu124（为抢时间使用系统
CUDA 库 + pip 的 cudnn/nccl）。训练窗约 25 分钟，15 代全部完成。

## 配置

| 项目 | 值 |
|---|---:|
| 代数 | 15 |
| 每代自对弈 | 200 局 |
| 每代样本 | 10,400（≥10,000 硬约束） |
| 每手搜索 | 30 ms |
| 模型 | 16 通道 × 2 残差块 |
| 训练 | 50 epoch，batch 512，CUDA AMP |
| 回放 | 最近 4 代 |
| 晋升 | 20 局，15 ms/手，得分率 ≥0.52 |
| 阶段 ELO | gen 0/5/10/14，4 局/对，15 ms/手 |

## 模型规格与训练量

KataGo 记法：**b2c16**（2 个残差块、16 通道）。

| 项目 | 数值 |
|---|---:|
| 参数量 | 13,210 |
| float32 权重文件 | 52,868 字节（约 52 KB） |
| 输入 | 19 × 9 × 9 平面 |
| policy | 729 个 `(格子,数字)` logits |
| 全局特征 | 22 维（双方手牌、行棋方、局面分、手数、空格） |
| 单次推理 | 约 982k MAC ≈ 1.96 MFLOP |
| 理论感受野 | 5 层 3×3，覆盖整个 9×9 棋盘 |

训练量：

- 自对弈：15 代 × 200 局 = **3,000 局**
- 唯一局面：15 × 10,400 = **156,000**
- 每代 50 epoch，回放最近 4 代
- 回放样本呈现：约 **5.62×10^5 / 轮**，50 epoch 共约 **2.8×10^7 次样本呈现**
- 约 **55,000 个 optimizer step**（batch 512）
- 自对弈 30 ms/手；训练在 RTX 3080 上约 0.2–0.7 s/epoch（首 epoch 有 CUDA 预热）

## 关键结论

### 1. 阶段 ELO 没有单调上升

`mcts_nn` 阶段 ELO：

```text
gen0  453.6 [277.8, 679.0]
gen5  139.0 [-280.2, 451.7]
gen10 383.0 [155.1, 504.1]
gen14 383.0 [155.1, 504.1]
```

12 局/引擎的 CI 很宽，不能据此断言“代际变强/变弱”；但方向不是稳定上升。

### 2. 20 局晋升门噪声很大，后续模型实际退化

用更多局复核（30 ms/手）：

| 候选 | 对 gen0 得分 | 胜/平/负 |
|---|---:|---:|
| gen4 candidate | 0.333 | 10/0/20 |
| gen6 candidate | 0.367 | 11/0/19 |
| gen8（最终文件） | 0.225 | 13/1/46 |
| gen14 candidate | 0.050 | 1/1/28 |

gen4 在 20 局晋升局里曾以 0.675 击败 gen0，但 30 局复核只有 0.333。
**20 局门不可靠**，这正是需要阶段 ELO 的原因。

### 3. 但新 gen0 显著强于旧 v1 基线

gen0 对旧 `models/shuyi_resnet_v1.bin`，60 局、30 ms/手、2 手随机开局：

```text
57 胜 / 0 平 / 3 负，得分率 0.950，ELO 差 +511.5，平均分差 +15.6
```

因此本次**最终部署选择 gen0**，不是流水线最后写出的 gen8。
`models/shuyi_resnet_v2.bin` 已用 gen0 权重覆盖；旧 v1 保留作对照。

### 4. 最终 gen0 ELO

用 gen0 跑 8 局/对、20 ms/手：

## 真实教训

1. 训练 loss 从 gen0 的 5.71 降到 gen14 的 3.51，但**强度没有同步上升**；
   它更像是在拟合回放数据里的 MCTS 分布，而不是变强。
2. 晋升门只有 20 局，方差足以让弱模型晋级（gen4/gen8）；必须用阶段 ELO
   或 60 局以上的门。
3. 本小时的正确部署选择是 gen0。下一轮应该：
   - 晋升门至少 60 局，或直接用阶段 ELO 做门；
   - 只有通过更大对局验证的候选才进入自对弈链；
   - 检查 replay 比例/学习率，避免后期模型“低 loss、低强度”。
