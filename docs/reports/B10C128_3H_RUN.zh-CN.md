# b10c128 3 小时实跑：105,750 steps / 2.34M 数据点

## 模型

KataGo 记法：**b10c128**。

| 项目 | 数值 |
|---|---:|
| 残差块 / 通道 | 10 / 128 |
| 参数量 | **2,975,994** |
| 文件大小 | **11,904,004 字节（约 11.9 MB）** |
| 输入 | 19 × 9 × 9 |
| policy | 729 个 `(格子,数字)` logits |
| 单次推理 | 约 **240.8M MAC / 481.5 MFLOP** |
| 最终文件名 | `b10c128-s105750-d2340000.bin` |

命名按 `b{blocks}c{channels}-s{steps}-d{data}`：

- `s105750` = 15 代累计 optimizer steps
- `d2340000` = 15 × 3000 局 × 52 个训练局面

## 训练量

| 项目 | 数值 |
|---|---:|
| 代数 | 15 |
| 每代自对弈 | **3,000 局** |
| 每代样本 | **156,000**（3,000 × 52） |
| 唯一局面总数 | **2,340,000** |
| 每代 epoch | 50 |
| batch | 1024 |
| 回放窗口 | 仅当前代（replay=1） |
| 累计 optimizer steps | 105,750 |
| 自对弈搜索 | 10 ms/手 |
| 训练 | RTX 3080, CUDA AMP，约 7.3 s/epoch |

## 收敛

| 代 | val | policy | value | top1 | top5 | value MAE |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | 3.861 | 3.786 | 0.150 | 2.8% | 12.9% | 0.322 |
| 14 | 3.883 | 3.753 | 0.260 | 2.4% | 11.7% | 0.363 |

- policy loss 略降（3.786 → 3.753）
- **value loss 明显变差（0.150 → 0.260）**
- val 总 loss 从 3.861 升到 3.883
- 开局 corner：0.089 → 0.094，区间 0.075–0.125，没有持续下降

## ELO

最终 b10c128 的 6 局/引擎阶段 ELO：

```text
mcts_nn = 299.0  [-300.7, 515.2]
```

作为对比，上一轮 b2c16 的最终 24 局/引擎 ELO 是：

```text
mcts_nn = 598.0  [462.4, 777.9]
```

b10c128 的阶段 ELO **没有上升**。6 局样本的 CI 很宽，不能证明它必然更弱，但也没有任何证据支持“换大模型就变强”。

## 我的诊断

上一轮的问题确实包括：

1. **b2c16 太小**：13,210 参数，policy 输出 729 类；top1 只有 2–3%，明显容量不足。
2. **数据太少**：每代 10,400 局面，总量 156,000，远不足以训练稳定 policy。

但这次 b10c128 + 2.34M 数据仍然没有变强，原因不是“数据分布”四个字可以带过的：

1. **教师搜索太弱**：b10c128 在 CPU 上一步推理约 0.3 s；3000 局 × 15 代无法用 b10c128 自对弈。本次只能用上一轮 b2c16 以 **10 ms/手** 生成数据。这个 teacher 的 policy target 本身噪声很大，b10c128 只是更忠实地拟合噪声。
2. **value 漂移**：value loss 从 0.150 升到 0.260，说明后续代在 value target 上发生了分布漂移/过拟合；policy loss 降低没有转化为强度。
3. **没有真正的迭代自对弈**：15 代数据都来自固定 b2c16 teacher，b10c128 没有用自己的搜索生成新数据。这更像“大模型蒸馏弱 teacher”，不是 AlphaZero 式闭环。
4. **训练目标单一**：replay=1、每代只在当前 156k 上跑 50 epoch，缺少跨代回放和稳定性约束；val 从 gen0 起就没有改善。
5. **评估样本仍太少**：最终 ELO 只有 6 局/引擎，CI 跨越 0；20 局、60 局门会更可靠，但 b10c128 CPU 对局约 18 s/局，3 小时内跑不起大样本。

结论：**容量和数据量是必要条件，不是充分条件。** 这台 8 vCPU + 3080 上，b10c128 的瓶颈已经变成 **自对弈推理**，不是训练。继续堆数据/epoch 而不解决 GPU batch MCTS，仍会得到“低 loss、低强度”的模型。
