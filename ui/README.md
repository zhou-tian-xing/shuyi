# ui/ — Win32 前端（一个独立产品）

原生 GDI 窗口，**不依赖浏览器，也不含任何搜索**。界面是规则与状态的权威：它维护棋谱与局面、
校验着法、绘制棋盘；一切计算都发给 `shuyi_engine.exe` 子进程，通过行协议（stdin/stdout）
接收 100 ms 一次的分析流。

```
include/game_record.h      棋谱树：每一着、每一枝，以及每个局面缓存的分析
include/engine_client.h    子进程 + 管道 + 读线程 + 同步握手 command()
include/engine_view.h      分析视图 + parseAnalysis()（JSON → 视图）
include/json.h             极简 JSON 解析器
include/discovery.h        引擎候选路径 + capabilities 探测
src/ui_win32.cpp           窗口、菜单、布局、绘制、按键与鼠标
src/game_record.cpp        棋谱树、保存/加载、与上一手预测的差值
src/engine_client.cpp      进程/管道/读线程
src/engine_protocol.cpp    解析 info JSON、着法 token
tests/test_game_record.cpp 棋谱树的单元测试（ctest: shuyi_ui_record）
tests/test_engine_view.cpp 分析解析的单元测试（ctest: shuyi_ui_view）
tests/ui_menu_smoke.py     无界面检查模型菜单（ctest: shuyi_ui_menu）
tests/engine_choice_smoke.py 无界面检查“用户选的引擎优先”（ctest: shuyi_engine_choice）
tests/a_value_smoke.py     驱动窗口检查设置与 A值（ctest: shuyi_ui_a_value）
```

## 窗口布局

```
 文件  模式  规则  引擎  帮助              ← 菜单栏：所有非落子的动作
┌──────────────┬────────────────┬──────────────┐
│ 行棋方        │                │ 棋谱          │
│ 胜率 / 目差   │      棋盘       │  起          │
│ 胜率横条      │                │ 1 e5-1   ▌   │
│ AI评估        │                │ 2 a5-1   ▌   │ ← 左边小块：相对上一步
│ 选点          │                │   2 c3-2 ▌   │ ← 变着，缩进
│ 当前分值      │                │ 3 e6-4   ▌   │
│ 走势折线      │                │ 4 h6-5   ▌   │
└──────────────┴────────────────┴──────────────┘
  A值 −/+  红 1¹2³3³… / 黑 1²2³3³…              第 N 手
            ↑ 右上角小数字：这种数字还剩几颗
```

* **左侧是分析的产物**：行棋方、最优线路的胜率与目差、双方胜率横条、AI 评估
  （这次的搜索花了多少、多快，例如 `4.2k 次 · 1.6k/秒 · GPU`；模型是用户自己选的，
  摆在面板里只是复述他的选择）、选点列表（每个着法一行，带胜率条与分值）、当前分值
  （原“若现在终局”），以及这条线上已分析局面的胜率/目差折线（始终红方视角，未分析的点断开）。
* **右侧是棋谱**，排得像一张棋谱纸：一行一手，行首是手数，主干往下接着走；换一个走法会在那一手
  后面缩进出一段变着，读完变着再回到主干。不按深度分列，是因为 54 手就是 54 列，而这块面板只有
  246 px 宽。每行左边有一小块颜色，是“这一手比上一步的评估好多少”：明显更好是蓝色（引擎当时
  没算过这一手，结果超出了它对局面的判断），不差是绿色，差是红色，与棋盘标记同一套映射。它是一
  小块，不是整行底色，选中这一行时也照样在。点击任何一行就回到那个局面，原来的分析还在。
* **下方只有 A值和剩余棋子**，都缩小成一条；每格棋子右上角的小数字是这种数字还剩几颗
  （`9³` = 还有三颗 9，`9⁰` 已用完，格子同时变暗）—— 以前只有“变暗/不变暗”两种状态，
  看不出还剩一颗还是三颗。键盘说明在 帮助 → 使用指南。

## 操作

* 数字键 1–9 或点击下方棋子：选择落子数字；点击棋盘落子。
* 空格：开始 / 暂停分析；达到访问上限后再按一次继续，不再限量。
* ↑ / ↓：在棋谱里上一步 / 下一步（↓ 走主干）。
* Delete：删除当前着法及其后续，连同它们的分析缓存。
* Ctrl+S：保存棋谱（菜单里写着这个键，因为一个快捷键只有写出来才算存在）。
* **翻棋谱不会让电脑落子**：看看前面几手、或者打开一局旧棋谱，都不该悄悄多出一着。轮到时面板
  会写“轮到电脑”，要它走一步用 **引擎 → 让电脑走一步**。电脑只在三种情况下落子：新开一局它执
  先、人类落子之后、以及这条菜单命令。
* 其余都没有快捷键：新局 / 保存棋谱 / 载入棋谱 / 退出在 **文件** 菜单里，规则与设置各在自己的菜单里。

## 构建（不需要引擎源码）

```bash
cmake -S ui -B build-ui -DCMAKE_BUILD_TYPE=Release
cmake --build build-ui
```

界面只链接 `../core`（规则）。它**不认识** `shuyi_search`：CMake 里没有这个依赖，
加回去就等于把引擎塞进界面包。

## 引擎从哪来

界面只是启动一个子进程，所以重要的是那个程序说不说协议，而不是它是谁编译的。顺序：

1. `SHUYI_ENGINE` 环境变量；
2. `shuyi-ui.ini` 里的 `engine=`（相对路径按本 exe 所在目录解析）；
3. 自动探测：exe 同目录 → `../build-cuda` → `../build` → 当前目录，取第一个
   `capabilities` 回 `proto=2` 的程序；多个可用时优先 `cuda=1`。

探测到之后用 `capabilities` 做**硬校验**：`proto != 2` 直接拒绝并弹窗说明，不做“可能兼容”。
启动时每条命令都同步等回复（`EngineClient::command`），任何 `?` 都会中止启动并弹窗，
不会带着半个配置继续跑。

## 三条硬规矩

1. **不计算**：没有引擎就什么都不算，绝不自己走一步。
2. **不猜**：引擎报错、分析 JSON 解析失败，都显示错误，不拿旧数据或空白冒充结果。
3. **口径一致**：棋盘标记、选点列表、胜率与目差都用“已解算则精确值，否则 Wilson 95% 下界”；
   目差只在引擎确实有分数时显示，没有就 `--`。

## 棋谱文件

`保存` / `载入` 读写 UTF-8 文本，每一着写作 `a4-2`，变着写在括号里：

```
# shuyi record v2
ruleset nopass
moves e5-1 a5-1 (c3-2 d4-3) e6-4
#node e5-1 wr 0.5312 visits 512 proven 0 nodes 4213 ms 380 best a5-1 score 1.5000 backend cuda
#cell e5-1 a5-1 0.5312 512 0 1 1.5000
#cand e5-1 a5-1 0.5312 512 1.5000
```

* 文件里带着规则集，因为同一串着法在不同规则下不是同一局棋。
* `#node` / `#cell` / `#cand` 是**可选**的分析：一个局面一行 `#node`，它算过的每个格子一行
  `#cell`，候选着法一行 `#cand`。路径写的是到达那个局面的着法（`a4:2/b2:5`，空棋盘是 `.`），
  不是节点编号——编号是树的实现细节，删一枝就变了。载入时这些数字回到对应的局面，棋盘标记、
  选点列表和坐标图立刻可用，不必重算。
* 三个前缀都是 `#`，也就是注释：只有 `moves` 的旧程序打开一个带分析的棋谱，看到的是同一局棋，
  只是没有数字。
* `shuyi.exe --open game.syp` 可以按这个格式直接打开（也便于把 `.syp` 关联到本程序）。

分析是**附加**的：某个局面已经有分析时，新结果只有在搜得不少于它的时候才覆盖它。因此重开引擎、
或者打开一个已经带着数字的棋谱，都不会让面板先空一下再慢慢爬回来。

## 测试用的无界面探针

`--dump-engine` / `--dump-models` 写出一份诊断文本，`ui/tests/` 里的脚本据此检查引擎发现与
模型菜单，不需要 GUI 会话。`tools/shoot_window.ps1` 与 `tools/drive_window.ps1` 是开发时用的
截图/驱动脚本（PrintWindow 抓图，按客户区坐标点击），用来在没有肉眼的情况下检查布局。
